Connection help

Support

Start by checking your device, network, and server. These steps cover the most common Jiaying connection problems.

Requirements

  • iPhone or iPad running iOS/iPadOS 18.0 or later.
  • Apple TV running tvOS 17.0 or later.
  • Network access from the device to your NAS, Family Media, or Jellyfin server.
  • Local Network access for Jiaying when first connecting to a home server.

Deploy Family Media

To read folders directly from your NAS, start with the NAS server download and installation guide. You do not need the Family Media server when connecting only to an existing Jellyfin server.

Connect your server

  1. Confirm that the server is running and note its device-accessible address and port.
  2. Place the Apple device on the same home network, or connect through a secure network you trust.
  3. Add the Family Media address in Jiaying, or enter the Jellyfin address and sign in.
  4. Open a folder, then test one photo and one video.

Do not enter localhost.

On an iPhone, iPad, or Apple TV, localhost means that Apple device, not your NAS. Use a NAS hostname or local address the device can reach.

Common problems

The server cannot be reached

Check Local Network permission, Wi-Fi, the server address and port, and whether the service is running. Also confirm that guest-network isolation is not blocking devices from reaching one another.

Jellyfin sign-in fails

Verify the same server address and account in a browser first. Jiaying does not store the Jellyfin password, so it must be entered again when signing in.

A photo or video will not open

Confirm that the original file exists and that the server can read it. Jellyfin can transcode some incompatible videos. Family Media does not transcode video.

Settings are missing on another device

This is expected. Jiaying stores configuration on each device and does not sync server addresses or Jellyfin sessions between devices.

Contact support

Email familymedia_app@163.com. You can also use Jiaying Support Issues for an anonymized report.

Do not post sensitive information in a public issue.

Never include passwords, tokens, real server addresses, device identifiers, or media names. Use example addresses and anonymized descriptions.
